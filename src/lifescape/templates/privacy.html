Hosted Lifescape server

Privacy policy

Last updated: November 24, 2026

The short version

The Lifescape Claude plugin connects to the hosted server at https://lifescape.buildproven.ai/api/mcp. You sign in with your GitHub account. The server keeps your research packets and run report indexes in the deployment owner's own database, stored under your GitHub login. Only you can read them through Lifescape, and delete_my_data removes them. The server does not sell, share, or analyze the data. It sets one short-lived cookie during sign-in, to tie the GitHub sign-in to the browser that started it, and no tracking cookies.

What the hosted server stores

The server writes these records to the owner's own database (Postgres, such as Neon). Each record is stored under your GitHub login, the login GitHub confirmed when you signed in:

  • Research packets (table research_packets): the search profile and research brief you give, the candidate towns, the evidence values fetched for them with their sources and observation dates, and your approvals and rejections.
  • Comparison report indexes (table run_report_indexes): for each comparison run, the names of the report files it wrote, their SHA-256 digests, and the report text that export_report returns.

Only you can read them through Lifescape: each tool reads and writes only the records stored under the signed-in GitHub login, so another user's packet or run reads as not found. The deployment's owner runs the database and can see its rows there. The comparison report files themselves are written to the server's temporary working directory, which the hosting platform clears; they are not kept elsewhere. The server does not store your GitHub password or your GitHub access token.

The landing page and the demo store nothing. The demo uses invented evidence and runs no account.

Who can sign in

Claude signs in through GitHub, and the tools answer 401 without a valid token. When signup is open, any GitHub account can sign in, and each account gets its own records. If the deployment's owner closes signup, the rule is stricter. Only the owner's GitHub account can sign in then: the server gives a token only to the GitHub login set as the deployment's owner, and every other GitHub account is refused.

Services that handle the data

  • GitHub confirms the signed-in login.
  • Vercel runs the server.
  • The owner's database provider (such as Neon) holds the records above.
  • Public data sources (the U.S. Census Bureau and NOAA) get the place you ask about when you fetch live evidence. They do not get your profile.

Each service handles data under its own privacy policy.

Delete your data

  1. Ask Claude to delete your Lifescape data. It calls delete_my_data, which removes every research packet and run report index stored under your GitHub login and returns how many of each it deleted. Other users' records stay. The delete cannot be undone.
  2. To stop all access, remove the Lifescape connector in Claude and revoke the Lifescape OAuth app in GitHub (Settings, then Applications).
  3. The deployment's owner can also delete records in the database itself: one user's with DELETE FROM research_packets WHERE owner = '<login>'; and the same statement on run_report_indexes, or all of them by deleting the database (in Neon: the project's settings, then Delete project).
